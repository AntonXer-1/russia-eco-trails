# Сайт маршрутов — план реализации

Дата: 10.11.2026. Основание: тетради 9–11 и согласованная преподавателем замена предметной области. Пользователь поручил приступать без повторных согласований обычных шагов.

## Решение

Отдельный репозиторий russia-eco-trails. HTML/CSS/JavaScript, локальный Bootstrap 5.3.8 из проверенного предыдущего проекта, без сборщика и backend. Четыре страницы: index.html, catalog.html, route.html, preparation.html. Общий подвал с контактами и меню; шапка sticky-top. На главной двухколоночный hero, преимущества, популярные маршруты и FAQ-accordion. В каталоге шесть маршрутов, поисковая строка, фильтры по сложности и длине, сброс, счётчик и пустой результат. Страница route.html?id=... показывает соответствующий маршрут и таблицу характеристик; неверный ID даёт понятное сообщение. Подготовка: список вещей и советы. Общий Bootstrap modal содержит учебную форму с обязательными label/name/required, form-control/form-select/input-group/form-check, browser-валидацией и alert-результатом. Форму не отправлять и не сохранять.

Фотографии хранить локально и указывать происхождение. Сведения о маршрутах брать из официальных источников, не заявлять актуальное открытие маршрутов; условные оценки сложности обозначить как редакционные. Простая зелёно-белая палитра, Arial, обычные карточки без декоративных усложнений.

## Файлы и проверки

- js/routes.js: небольшой массив данных, route ID, название, регион, длина с пояснением способа измерения, условная сложность, описание, фото, источник.
- js/main.js: фильтрация статических карточек, подстановка данных страницы маршрута и выбранного маршрута формы, учебная обработка формы.
- css/custom.css: небольшие дополнения к Bootstrap.
- tests/site.test.cjs: реальные browser-сценарии поиска/фильтров/сброса/пустого результата, переходы на нужный маршрут, плохой ID, modal/формы, мобильное меню и отсутствие переполнения.
- README и docs/DEFENSE.md: требования каждой практики, адаптация имён страниц, локальное подключение вместо CDN, где показывать компоненты, ограничения и источники.

## Шаги

1. Подготовить репозиторий, данные и локальные ресурсы. Написать тесты сценариев и убедиться в падении до реализации.
2. Создать четыре страницы и обработчики. Запустить проверки, посмотреть компьютерную и мобильную версии, исправить найденное.
3. Сверить результат с тетрадями, подготовить README и памятку защиты. Независимое ревью, затем GitHub PR и публикация Pages; проверить опубликованные файлы. Обновить общий AGENTS.md фактическими ссылками и статусом.

## Особые проверки

Пустой или пробельный поиск; несовместимые фильтры; неизвестный ID в адресе; повторное открытие формы для другого маршрута; неверный email/телефон и отсутствие согласия; отсутствие отправки данных; ширины 375/768/1280; состояние без JavaScript.
